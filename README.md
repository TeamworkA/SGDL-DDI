# SGDL: Substructure-Aware Global Dependency Learning for Drug–Drug Interaction Event Prediction

This repository provides the implementation, datasets, and supplementary material associated with the following work:

**Substructure-Aware Global Dependency Learning for Drug–Drug Interaction Event Prediction**

The proposed method is **SGDL (Substructure-Aware Global Dependency Learning)**. It is designed for multi-class drug–drug interaction (DDI) event prediction by combining chemically meaningful molecular substructure information with relation-aware and global drug dependency representations.

> **Naming note:** SGDL is the proposed method in this work. `MRCGNN` is the name of a baseline method discussed in the paper, not the name of the proposed model. The directory `codes for MRCGNN/` is retained exactly as it appears in the supplied code archive; its folder name has not been changed in order to preserve the original project paths.

## 1. Method Overview

SGDL addresses two limitations in DDI event prediction:

- **Molecular representation:** conventional atom-level message passing may not explicitly preserve the semantics of chemically meaningful molecular fragments.
- **Drug dependency modeling:** methods that rely only on observed DDI edges may fail to capture latent relationships between drugs that are not directly represented in the observed interaction topology.

SGDL consists of the following components:

1. **Fragment-aware molecular representation.** BRICS decomposition is used to obtain chemically meaningful molecular fragments. PageRank scores of constituent atoms are aggregated to characterize the structural importance of each fragment, producing BRICS-derived drug feature vectors.
2. **Relation-aware DDI graph representation learning.** A relational graph convolutional network (R-GCN) aggregates relation-specific information from the multi-relational DDI event graph. Pretrained molecular representations are used as the initial drug features.
3. **Substructure-guided global dependency learning.** BRICS-derived drug profiles are projected into a latent space and used as structural cues for global dependency modeling. The module uses kernelized attention to capture latent dependencies among drug nodes without explicitly constructing a dense pairwise attention matrix.
4. **Contrastive representation enhancement.** The original BRICS feature matrix forms the positive view, while a corrupted view is generated by randomly permuting BRICS feature assignments across drug nodes. A contrastive objective encourages discriminative global drug representations.
5. **Feature fusion and DDI event prediction.** Relation-aware and global dependency representations are concatenated. The fused drug representations are combined with the original molecular features of each drug pair and fed into an MLP with a Softmax classifier to predict DDI event types.

The overall training objective combines the DDI prediction loss, contrastive loss, and graph structure regularization loss.

## 3. Datasets

Experiments in the paper are conducted on two benchmark DDI event prediction datasets.

| Dataset | Drugs | DDI records | Event types |
|---|---:|---:|---:|
| Deng | 572 | 37,264 | 65 |
| Ryu | 1,700 | 191,570 | 86 |

- **Deng dataset:** derived from DrugBank 3.0.
- **Ryu dataset:** derived from DrugBank 5.0.

Following the experimental protocol described in the paper, each dataset is randomly divided into training, validation, and test subsets at a ratio of **7:1:2**. Five random splits are used, and the reported results are averaged over the five runs. The multi-relational DDI graph used by R-GCN is constructed only from training interactions to avoid incorporating validation or test interactions into graph construction.

The archive contains the five split directories (`0`–`4`). Dataset files are retained in their original locations.

## 4. Experimental Results

The paper reports the following results on the Deng and Ryu datasets. Macro-F1 is used as the primary metric because DDI event categories are imbalanced.

| Dataset | Accuracy | Macro-F1 | Macro-Precision | Macro-Recall |
|---|---:|---:|---:|---:|
| Deng | 0.9089 | 0.7951 | 0.8233 | 0.7828 |
| Ryu | 0.9652 | 0.9157 | 0.9478 | 0.8857 |

The paper also reports ablation studies on both datasets, including variants without pretrained molecular embeddings, substructure features, R-GCN, the global dependency module, and contrastive learning.

### Dependency installation note

The supplied `requirement.txt` includes local wheel references for `torch-scatter` and `torch-sparse` that point to a path on the original development machine (`/mnt/xzk/...`). Those wheel files are not included in this repository. Therefore, installing directly with `pip install -r requirement.txt` may fail at these entries. Install compatible builds of these packages for the selected Python, PyTorch, CUDA, and PyTorch Geometric versions before running the project.

## 7. Running the Experiments

The supplied `5timesrun.py` script is intended to launch five runs, using split indices `0` to `4`.

From the code directory, the invocation shown by the script is:

```bash

python 5timesrun.py
```

A single run is invoked by the script in the following form:

```bash
python main.py --out_file test.txt --zhongzi 0
```

### Important reproducibility note

The code archive provided for this repository is not currently a self-contained, directly executable release. Inspection of the supplied files shows that:

- `main.py` imports `data_preprocess_test2.py` and `train_test2.py`, which are not present in the archive.
- `instantiation.py` imports `MRCGNN` from `layer_test3.py`, which is not present in the archive.
- The preprocessing implementation references `feature/drug_emb_feature0.npy` and `feature/drug_emb_feature0_drug_ids.npy`, which are not present in the archive.
- `requirement.txt` contains machine-specific local wheel paths, as described above.

These files and paths have not been reconstructed or modified. The commands above document the entry points visible in the supplied code; successful execution requires the missing modules and feature files, as well as compatible dependencies. Please do not interpret the current archive as a verified one-click reproduction package.
